## Findings

<a id="m1"></a>
### M1 — Session ที่ถูก revoke อาจกลับมาใช้ได้และไม่มีวันหมดอายุ

**ระดับ:** Medium · **มาตรฐาน:** OWASP A07:2021 Identification and Authentication Failures · ASVS 3.3.1, 3.3.3

**ปัญหา**

`touch()` อ่าน session ด้วย `GET` แล้วค่อยเขียนกลับด้วย `SET ... KEEPTTL` ใน `MULTI` ภายหลัง (`session.service.ts:79-88`) ถ้ามีการลบ session นั้น**ระหว่าง** `GET` กับ `EXEC` คำสั่ง `SET` จะสร้าง key ใหม่ขึ้นมา `listForUser()` บรรทัด 124 ก็มีปัญหาแบบเดียวกัน การลบที่ว่านี้ได้แก่ เปลี่ยนรหัสผ่าน, Admin reset รหัส, Sign out other devices, Admin revoke และ Anonymize

ทดลองกับ Redis ในโปรเจกต์แล้ว:

```
SET t:x v KEEPTTL       → OK
TTL t:x                 → -1    (ไม่มีวันหมดอายุ)
SET t:x v XX KEEPTTL    → (nil) ไม่สร้าง key
```

**ผลกระทบ**

- session ที่ควรถูกตัดกลับมาใช้ได้**ถาวร** เพราะไม่มี TTL
- session นั้นหายไปจาก set `user-sess:<userId>` แล้ว จึงไม่แสดงในหน้า Sessions และ `destroyAllForUser()` ครั้งถัดไปก็ลบไม่ได้
- ตัวอย่าง: Admin reset รหัสให้บัญชีที่ถูกขโมย cookie แต่ผู้โจมตียังใช้ cookie เดิมได้
- **สิ่งที่ยังป้องกันอยู่:** กรณีถูกระงับ (`isActive = false`) ยังปลอดภัย เพราะ `AuthGuard` ตรวจ `isActive` ทุก request

**โอกาสเกิด:** ต่ำ เพราะ `touch` เขียนกลับแค่นาทีละครั้งต่อ session และช่วงเวลาที่ชนกันได้สั้นมาก (ระดับมิลลิวินาที) แต่ผู้โจมตีที่ยิง request ถี่ๆ เพิ่มโอกาสได้ และถ้าเกิดแล้วแก้ไม่ได้จาก UI

**วิธีแก้**

ใส่ `XX` เพื่อเขียนเฉพาะ key ที่ยังอยู่ (Redis รับ option ตามลำดับไหนก็ได้):

```ts
// session.service.ts — touch()
multi.set(key, JSON.stringify(data), 'KEEPTTL', 'XX');

// session.service.ts — listForUser()
await this.redis.client.set(`sess:${id}`, JSON.stringify(data), 'KEEPTTL', 'XX');
```

ถ้า type ของ ioredis ไม่รับลำดับนี้ ให้ใช้ `this.redis.client.call('SET', key, value, 'XX', 'KEEPTTL')`

**ป้องกันอีกชั้น (แนะนำ):** ใน `touch()` ให้ตรวจ `SISMEMBER user-sess:<userId> <id>` ใน `MULTI` เดียวกัน ถ้าไม่อยู่ใน index ให้ถือว่า session ไม่ valid

**Test ที่ควรเพิ่ม:** unit test ที่ลบ key ระหว่าง `get` กับ `exec` (mock redis) แล้วยืนยันว่า key ไม่ถูกสร้างใหม่

<a id="m2"></a>
### M2 — ทำให้ระบบไม่เหลือ Admin ที่ active ได้

**ระดับ:** Medium · **มาตรฐาน:** OWASP A04:2021 Insecure Design · ASVS 1.4.1 (business logic integrity)

**ปัญหา:** กฎ "ห้ามระงับ Admin คนสุดท้าย" ตรวจแค่ตอน**สร้าง**การระงับ (`suspension.service.ts:71`) แต่มีอีก 3 ทางที่ไม่ได้ตรวจ:

1. **PATCH เปลี่ยน role** (`users.controller.ts:403-405`) ห้ามแค่ลด role ของตัวเอง แต่ลด role ของ Admin คนอื่นได้เสมอ
2. **Scheduled job** (`applyScheduled`, บรรทัด 213) ไม่ตรวจซ้ำตอนการระงับมีผลจริง
3. **การระงับพร้อมกัน** ไม่มี lock ระหว่างการตรวจกับการเขียน (TOCTOU) Admin 2 คนจึงระงับกันเองพร้อมกันได้ และผ่านการตรวจทั้งคู่

**ตัวอย่างที่เกิดได้จริง** (มี Admin A และ B):
1. B ตั้งระงับ A ล่วงหน้าเป็นวันศุกร์ (ผ่านการตรวจ เพราะ B ยังเป็น Admin)
2. วันพุธ A เปลี่ยน role ของ B เป็น MEMBER (PATCH ไม่ตรวจ)
3. วันศุกร์ job ระงับ A → **ไม่เหลือ Admin ที่ active**

**ผลกระทบ**

- ไม่มีใครจัดการผู้ใช้, เปิดบัญชีคืน หรือดู audit log ได้
- `seed.ts` จะไม่สร้าง Admin ใหม่ให้ เพราะนับ `role = 'ADMIN'` โดยไม่สนว่าบัญชีถูกระงับอยู่หรือไม่
- ต้องแก้ฐานข้อมูลโดยตรงจึงจะกู้คืนได้

**วิธีแก้**

1. **ทำ helper ตัวเดียวแล้วเรียกใน transaction:**
   ```ts
   /** Serialises every change that can remove an admin, then checks at least one usable admin remains. */
   async function assertAdminRemains(tx: Tx, leavingUserId: string) {
     await tx.$executeRaw`SELECT pg_advisory_xact_lock(hashtext('admin-invariant'))`;
     const others = await tx.user.count({
       where: {
         role: 'ADMIN', isActive: true, anonymizedAt: null, id: { not: leavingUserId },
         suspensions: { none: { status: { in: ['SCHEDULED', 'ACTIVE'] } } },
       },
     });
     if (others === 0) throw coded(HttpStatus.CONFLICT, 'LAST_ADMIN', 'At least one active administrator must remain.');
   }
   ```
2. **เรียก helper ในทุกเส้นทาง:**
   - `PATCH /admin/users/:id` เมื่อ `existing.role === 'ADMIN' && dto.role !== 'ADMIN'`
   - `suspend()` ย้ายการตรวจเข้าไปใน `$transaction`
   - `applyScheduled()` ถ้าไม่ผ่าน**ไม่ต้องระงับ** ให้คงสถานะ `SCHEDULED` ไว้ แล้วบันทึก audit `user.suspension_blocked` และ log error ให้ Admin เห็น
3. **แก้ `seed.ts`** ให้นับ `{ role: 'ADMIN', isActive: true, anonymizedAt: null }` เพื่อให้ตั้ง `ADMIN_EMAIL`/`ADMIN_PASSWORD` แล้ว restart เพื่อกู้ระบบได้ (เขียนขั้นตอนนี้ไว้ใน `docs/SETUP.md` ด้วย)

**Test ที่ควรเพิ่ม:** ลด role ของ Admin คนอื่นจนเหลือ 0, ทำตามตัวอย่างข้างบน, และยิง suspend พร้อมกัน 2 request

### M3 — `ua-parser-js` 2.x เป็น AGPL-3.0

**ระดับ:** Medium (ความเสี่ยงด้าน license ไม่ใช่ช่องโหว่) · **มาตรฐาน:** ASVS 14.2.1 (component inventory), นโยบาย license ขององค์กร

**ปัญหา**

```
ua-parser-js 2.0.10  AGPL-3.0-or-later
```

- ตั้งแต่ v2 เป็นต้นไป `ua-parser-js` เปลี่ยน license จาก MIT เป็น AGPL พร้อมขายรุ่น commercial แยก
- AGPL มีเงื่อนไขเรื่อง network use ซึ่งอาจบังคับให้เปิดซอร์สของ API ทั้งตัวให้ผู้ใช้งานผ่านเครือข่าย ระบบ enterprise ส่วนใหญ่ไม่อนุญาตให้ใช้ license นี้
- `@types/ua-parser-js@^0.7.39` เป็น type ของ v0.7 ไม่ตรงกับ v2 (v2 มี type มาในตัว) และใช้ `^` ขณะที่ dependency อื่นในโปรเจกต์ pin version ตายตัว

**วิธีแก้ (เลือก 1 ทาง)**

- ใช้ `ua-parser-js@1.0.41` (MIT) ซึ่ง API `UAParser(ua).getBrowser()/getOS()` ใกล้เคียงของเดิม
- หรือใช้ `bowser` (MIT)
- หรือเขียน regex เองสำหรับ browser/OS หลักๆ เพราะใช้แค่ทำป้าย "Chrome on Windows"

ไม่ว่าทางไหน ให้ลบ `@types/ua-parser-js` ออก หรือ pin ให้ตรงเวอร์ชัน และ pin `@types/multer` ด้วย

**ป้องกันในอนาคต:** เพิ่ม license check ใน CI (เช่น `pnpm licenses list --prod` แล้ว fail เมื่อเจอ AGPL/GPL)

### L1 — ไม่จำกัดขนาด pixel และจำนวนครั้งของการอัปโหลด Avatar

**ระดับ:** Low · **มาตรฐาน:** OWASP A04:2021 · ASVS 12.1.1, 12.1.2, 11.1.4

**ปัญหา**

- `sharp(input, { failOn: 'error' })` ใช้ `limitInputPixels` ค่า default (ประมาณ 268 ล้าน pixel)
- endpoint ไม่มี rate limit
- `FileInterceptor` จำกัดแค่ `fileSize` และ `files` ส่วน `fields`/`parts` ยังเป็นค่า default ของ multer คือไม่จำกัด

**ผลทดลอง** (sharp 0.35.5 ตัวเดียวกับในโปรเจกต์ รันในเครื่อง):

```
PNG 16000×16000 สีเดียว: 776,180 bytes (ผ่านเพดาน 2 MB)
decode + resize: 365 ms, peak RSS 143 MB ต่อ 1 request
```

**ผลกระทบ:** request เดียวไม่ทำให้ระบบล่ม แต่ผู้ใช้ที่ล็อกอินแล้วคนเดียวยิงพร้อมกันหลายสิบ request ได้ ใช้หน่วยความจำของ container `api` หลาย GB และกิน CPU จนกระทบห้องประชุมกับผู้ใช้คนอื่น

**วิธีแก้**

```ts
// avatar.service.ts
const MAX_INPUT_PIXELS = 4096 * 4096;
return await sharp(input, { failOn: 'error', limitInputPixels: MAX_INPUT_PIXELS, animated: false })
  .rotate().resize(AVATAR_SIZE, AVATAR_SIZE, { fit: 'cover', position: 'centre' }).webp().toBuffer();

// me.controller.ts และ users.controller.ts (import/preview)
FileInterceptor('file', { limits: { fileSize: AVATAR_MAX_BYTES, files: 1, fields: 0, parts: 1 } })
```

- ใช้ `RateLimitService` ที่มีอยู่แล้วจำกัด avatar ไว้ประมาณ 10 ครั้งต่อ 10 นาทีต่อผู้ใช้
- เรียก `sharp.concurrency(1)` ตอน bootstrap หรือใช้ semaphore เพื่อจำกัดจำนวนงาน decode ที่ทำพร้อมกัน

<a id="l2"></a>
### L2 — Query parameter ไม่ถูก validate ทำให้ตอบ 500

**ระดับ:** Low · **มาตรฐาน:** OWASP A03:2021 (input validation) · ASVS 5.1.3, 7.4.1

**ปัญหา**

- **`departmentId` ไม่ใช่ UUID:** `GET /api/directory?departmentId=abc` (ผู้ใช้ทุกคนเรียกได้) และ `GET /api/admin/users?departmentId=abc` ส่งค่าเข้า Prisma ตรงๆ คอลัมน์เป็น `@db.Uuid` จึงเกิด error และตอบ 500
- **parameter ซ้ำ:** `?q=a&q=b` ทำให้ Express ส่งค่ามาเป็น array แล้ว `q?.trim()` เกิด `TypeError` และตอบ 500 (`me.controller.ts:252`, `users.controller.ts:202`)
- **ตรวจ role ด้วย `in`:** `filters.role in UserRole` (`users.controller.ts:215`) รับค่า `constructor` หรือ `toString` ได้ เพราะ `in` นับ property ที่สืบทอดจาก `Object.prototype` ด้วย จากนั้น Prisma ตอบ 500
- **`exportCsv` รับ `@Query() query: UserFilters`:** `UserFilters` เป็น `interface` ซึ่ง `ValidationPipe` ตรวจไม่ได้ จึงไม่มีการ validate เลย

**ผลกระทบ:** ข้อความ error ภายในอาจหลุดลง log หรือ response และ log มี noise จนมองข้ามการโจมตีจริง

**วิธีแก้:** ทำ DTO class สำหรับ query แล้วใช้ร่วมกันทั้ง list และ export:

```ts
class UserListQuery {
  @IsOptional() @IsString() @MaxLength(100) q?: string;
  @IsOptional() @IsEnum(UserRole) role?: UserRole;
  @IsOptional() @IsIn(['ACTIVE', 'LEAVING', 'SUSPENDED', 'ANONYMIZED']) status?: string;
  @IsOptional() @IsUUID() departmentId?: string;
  @IsOptional() @IsIn(Object.keys(SORTS)) sort?: string;
  @IsOptional() @Type(() => Number) @IsInt() @Min(1) @Max(10_000) page?: number;
}
```

ทำ `DirectoryQuery` แบบเดียวกันสำหรับ `/directory`

<a id="l3"></a>
### L3 — Audit log `user.updated` เก็บค่าข้อมูลส่วนตัวจริง

**ระดับ:** Low (PDPA) · **มาตรฐาน:** ASVS 7.1.1, 8.3.4 · PDPA มาตรา 33 (สิทธิขอลบข้อมูล)

**ปัญหา:** `users.controller.ts:439-446` เก็บค่า**ใหม่**ของ `phone`, `firstName`, `lastName`, `employeeId` และ `displayName` ลงใน `metadata.changes` ทุกครั้งที่ Admin แก้ profile เมื่อ Anonymize แล้ว ค่าเหล่านี้ยังอยู่ใน `audit_logs` ซึ่งขัดกับเจตนาของ F8

สเปกยอมให้เก็บแค่ email ไว้ใน audit (D6) ส่วน `profile.updated` ที่ผู้ใช้แก้เองทำถูกแล้ว คือเก็บแค่ชื่อฟิลด์

**วิธีแก้**

- **ฟิลด์ข้อมูลส่วนตัว:** เก็บแค่ชื่อฟิลด์ เช่น `metadata: { fields: ['phone', 'firstName'], role?, departmentId?, emailFrom?, emailTo? }`
- **ค่าที่ไม่ใช่ข้อมูลส่วนตัว:** `role` และ `departmentId` เก็บค่าได้ตามเดิม
- **ข้อมูลเก่าที่ออกไปแล้ว:** ใน `anonymize()` ให้ล้าง `metadata.changes` ของ `user.updated` ที่ `target_id = userId` หรือบันทึกเป็นงานค้างใน Backlog เรื่อง audit retention

<a id="l4"></a>
### L4 — `importId` ไม่ผูกกับ Admin ที่ทำ preview และ claim แบบไม่ atomic

**ระดับ:** Low · **มาตรฐาน:** ASVS 4.2.1, 11.1.2

**ปัญหา**

- **ไม่ผูกกับเจ้าของ:** `commit()` (`import.service.ts:150`) ไม่ตรวจว่าคนที่ commit คือ Admin คนที่ทำ preview Admin คนอื่นที่ได้ `importId` (เช่นจาก log หรือ screenshot) จึง commit แทนและได้ไฟล์รหัสผ่านชั่วคราวไปได้
- **claim ไม่ atomic:** ใช้ `GET` แล้วค่อย `DEL` หลังสร้างบัญชีเสร็จ (บรรทัด 151 และ 202) การกด commit ซ้ำพร้อมกันจึงทำให้ hash argon2 500 ครั้งซ้ำสองรอบ ก่อนที่รอบที่สองจะชน unique constraint
- **ยืนยันไม่ได้ว่านำเข้าสำเร็จ:** ถ้า response หายกลางทาง ผู้ใช้ถูกสร้างแล้วแต่ไม่มีใครเห็นรหัสผ่าน ต้องไปไล่ reset ทีละคน

**วิธีแก้**

```ts
// preview
await redis.set(key, JSON.stringify({ adminId, rows }), 'EX', IMPORT_TTL_SECONDS);

// commit
const stored = await redis.getdel(key);                       // claim ครั้งเดียว
if (!stored) throw coded(HttpStatus.GONE, 'IMPORT_EXPIRED', ...);
const { adminId: owner, rows } = JSON.parse(stored);
if (owner !== adminId) throw new ForbiddenException();
```

ถ้า validate ไม่ผ่าน ให้เขียน key คืนพร้อม TTL เดิม เพื่อให้แก้ไฟล์แล้วลองใหม่ได้ ใน UI ให้บอกชัดเจนว่าถ้าดาวน์โหลดไม่สำเร็จ ต้อง reset รหัสของผู้ใช้ที่นำเข้า

## สิ่งที่ผ่านการตรวจ

- **สิทธิ์:** ทุก endpoint ของ Admin มี `@Roles('ADMIN')` ระดับ controller ส่วน endpoint ใหม่ของผู้ใช้ทั่วไปไม่รับ `id` ของคนอื่นในทางที่แก้ข้อมูลได้
- **บังคับเปลี่ยนรหัสผ่าน:** บังคับที่ server ใน `AuthGuard` ไม่ได้พึ่งแค่การ redirect ฝั่ง web
- **Directory:** กรองฟิลด์ที่ API (`directoryView`) จึงไม่มี `phone`, `employeeId` และ `role` หลุดออกไป
- **Avatar:**
  - ตรวจ magic bytes และ re-encode ทุกครั้ง จึงไม่มี EXIF/GPS เหลือ
  - ใช้ key ที่ server สร้างเอง ผู้ใช้ควบคุมชื่อไฟล์ไม่ได้
  - bucket เป็น private และ policy MinIO จำกัด `PutObject` แค่ `avatars/*` ส่วน Egress เขียนได้แค่ `meetings/*`
- **การระงับ:**
  - มี partial unique index กันการระงับซ้อน
  - job ใช้ claim ด้วย `updateMany ... WHERE status = 'SCHEDULED'` จึงรันซ้ำได้อย่างปลอดภัย
  - ตรวจผู้รับช่วงซ้ำอีกครั้งตอนการระงับมีผล
- **LiveKit:** webhook `participant_joined` เตะผู้ใช้ที่ `isActive = false` ออก แม้ token เดิมจะยังไม่หมดอายุ
- **Login:**
  - ยังรักษา timing ให้เท่ากันสำหรับ email ที่ไม่มีอยู่ (`dummyVerify`)
  - ข้อความ suspended แสดงเฉพาะเมื่อรหัสผ่านถูกตาม D10
  - rate limit ยังทำงานกับรหัสผิด
- **CSV:**
  - export มีกันสูตร (`= + - @ TAB CR`) และ quote ตาม RFC 4180
  - รหัสชั่วคราวสร้างด้วย CSPRNG (`randomInt`) ไม่ถูกเก็บไว้ที่ไหน และ response มี `Cache-Control: no-store`
- **Web:** `next` ในหน้า login ผ่าน `safeNext()` ไม่พบ `dangerouslySetInnerHTML` และไฟล์ดาวน์โหลดไม่ถูกเก็บใน state
- **SQL:** ใช้ Prisma query builder ทั้งหมด ไม่มี raw SQL ที่ต่อ string
